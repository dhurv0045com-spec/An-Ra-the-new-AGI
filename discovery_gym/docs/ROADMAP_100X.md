# Discovery Workbench 100× Utility Scorecard

This scorecard defines what “100× better” must mean for Discovery Gym. It is a measurement contract, not a claim that the multiplier has already been achieved.

## North-star metric

**Validated useful experiments per real interaction**, measured at a fixed target competence and including failed runs, preparation, execution, evaluation, recovery, and human intervention.

A useful experiment is one that changes a decision, reduces a declared uncertainty, or produces a transferable result. Repeating the same observation, collecting unlabelled rows, or generating a prettier report does not count.

## Current instrumented levers

| Lever | Baseline | Workbench measurement | Next improvement |
|---|---|---|---|
| Data readiness | coarse ready boolean | declared/materialized/verified/qualified/runnable states | connect exact owner qualification receipts |
| Inventory | sum of receipt rows | unique dataset identities, lineage conflicts, duplicate groups | canonical cross-receipt union and overlap audit |
| Discovery | one opaque score | graph hypothesis, edge support, topology stability, recovery precision/recall/F1, and majority/full-conditional/graph predictive comparison | equivalence-class and nonlinear discovery |
| Experiment choice | fixed/random schedule | ranked, costed intervention and measurement recommendations | outcome-calibrated expected utility |
| Continuity | rerun from scratch | append-only hash chain and replayable session | crash-safe event store and fresh-process executor |
| Claim control | aggregate accuracy | causal claim boundary and external executor identity | independent examiner and promotion gate |

## Required 100× experiment

1. Freeze one owner-supplied tabular fixture and its exact content hash.
2. Freeze a baseline investigator and the workbench investigator before confirmation.
3. Run both on the same fresh mechanism families with the same maximum real interactions.
4. Record every attempted experiment, invalid attempt, intervention assignment, outcome, cost, failure, and recovery event.
5. Evaluate fixed target competence, not the best checkpoint.
6. Compute useful experiments per interaction, cost to target competence, graph recovery quality, calibration, and transfer.
7. Report confidence intervals and all negative results.

The multiplier is accepted only if the improvement is large, uncertainty-bounded, attributable to the workbench, and does not rely on hidden labels, extra data, unequal budgets, or human tuning after confirmation.

## What is intentionally not counted

- A larger model with the same number of real interactions.
- A projection-head ratio multiplied by a data-packing ratio.
- A toy synthetic score with no external fixture.
- A benchmark selected after seeing the result.
- A report that omits failed runs, retries, or recovery cost.

The workbench is useful now because it makes those quantities measurable and preserves the evidence needed to improve them.
