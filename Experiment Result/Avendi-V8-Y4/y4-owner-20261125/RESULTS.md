**Decision, 25 November 2026.** Keep the categorical graph executor as a positive control. Models were trained on depths one and two. Each native confirmation depth had **64 eight-cell families per seed** (256 total across four depths). The plan called for 256 per depth per panel. Five seeds saw the same evaluation families. Percentages are equal-weight seed means.

The IIT arm missed one depth-four family at seed 73. Each comparator tied it in four seeds and beat it in one. The confirmation effect is **−0.15625 percentage points** against each comparator, with **0/5 positive seeds**. The required effect was at least +10 points and ≥4/5 positive seeds. The release JSON's 0-point estimate uses *development* scores. Its bootstrap takes five seed means as its input, and its McNemar test operates on five thresholded seed scores. The export lacks per-family confirmation predictions for an independent paired-family interval. The preregistered effect gate fails even without inference.

The categorical model learns row-key matching, receives parsed key/value IDs and the required step count, and copies row values into the next state through an engineered operation. The continuous result independently suggests recurrent row access can support longer composition here. The observed dense decline identifies a useful comparator; the provided width matching does not demonstrate matched active gradients and FLOPs.

**The causal claim needs a different measurement.** The training IIT loss does use a donor forward pass, but the evaluation builds its “donor” patch from the known entity ID (one-hot or embedding). The categorical oracle-injection score reuses the donor score; the nonlinear probe field copies the ridge accuracy. The “variable stop” panel supplies the correct step count again. These scores establish behavior under supplied state and depth. They do not establish native donor-state transfer, nonlinear decodability or learned stopping. The training loss also repeatedly slices the front of the same stored pair list, limiting intervention diversity. ## 2. Reading the prompt remains the immediate bottleneck

On confirmation every A, B and F arm recorded **0% four-cell and eight-cell success**. A correct family requires answering both queries, both edge assignments, and for eight cells both row orders. Individual cases were easier.

| S3 arm, five seeds | Confirm exact individual response | Dev literal exact | Dev first-byte change when the query requires a different first byte |
|---|---:|---:|---:|
| CE | 32.31% | 18.87% | 2.32% |
| Margin | 28.29% | 16.76% | 11.75% |
| Pointer | 27.38% | 16.74% | 4.56% |
| Pointer sham | 27.38% | 16.74% | 4.56% |

The last column is a fresh computation from the archive. I regenerated the native dev worlds, held edge assignment and presentation order fixed, and swapped only the queried key. There were 904 eligible pairs per seed after excluding equal first-byte targets. A changed prediction is necessary on these pairs but can still be wrong. Even the most sensitive arm rarely changed its first byte. S20 CE and low-LR CE achieved 24.37% and 27.36% individual confirmation accuracy and zero complete families.

**The pointer control had no effective intervention.** I regenerated the 4,096 selected training cells for each of five seeds. Shuffling spans within the same fixed-width templates changed **0/4,096** key/value/query span labels in every seed. All **20/20** matched dev logit files (four panels × five seeds) have identical content digests between pointer and sham. Their ~99.6–100% sampled parse scores show that the fixed-format spans are readable. The implementation exports parser accuracy and a pointer ablation instead of the planned learned-parser × learned-executor endpoint matrix. The archive cannot tell us whether connecting this parser to the typed executor would solve the original byte prompt.

There is also a training exposure defect. The generator orders cells by assignment, then query, then row orientation. The byte trainer takes `cells[:4]`, which includes both row orders for **only the first edge assignment**. Repeated epochs continue using the same subset. The margin loss also compares only the first output byte, which is uninformative when both candidate IDs begin with the same letter. The small-set diagnostic M uses the general byte job's training pool and only shortens the update count, so it cannot isolate the preregistered 32-family overfit experiment. ## 3. Executive action selection improved, but the task leaked its answer

| Fork, three-seed confirm mean | Labeled optimal action metric | Correct terminal answer after tool | Realized utility |
|---|---:|---:|---:|
| Direct + informative | 78.33% | 11.74% | −0.474 |
| Replace-direct label | 77.86% | 9.48% | −0.467 |
| Direct + neutral | 4.05% | 0% (no successful post-tool cases) | −1.821 |
| A→A | 5.48% | 0% (no successful post-tool cases) | −1.786 |

The action metric credits a tool selection separately from its downstream answer. The reported terminal statistic is conditional on selected tool calls, and the implementation emits zero when that denominator is empty. The informative arm missed the 80% macro and terminal gates. Its training examples supervise the first optimal action; they do not explicitly train the returned-edge-to-answer continuation. The replace-direct arm still allocates half its slots to direct examples from a different subset, so it does not test complete direct-dose replacement.

**A public-prompt-only control solved every world on both splits.** Parse the two advertised candidates and collect which ones already appear as destination values. If only one appears, answer with the other candidate. If both appear, follow the two public edges from the query. The construction makes this correct even on all 20 “unobtainable” and all 20 stale cases per split. This uses no private condition, tool flags, timestamps, feedback or training examples. With +1 for a correct answer, this policy earns **+1.0 utility** on all 280 worlds before any tool cost. Five labeled optimal actions per split request an unavailable tool. In 120/140 worlds per split the purported interior tool payload ends in the true terminal answer. These are fixture defects; they invalidate a learned value-of-information claim regardless of whether a particular model used the shortcut.

## 4. Memory, preservation and historical intake

- **E, learned writer.** On confirmation, unseen accuracy after relevant feedback was **24.09%**, compared with 24.61% without feedback, 27.73% with irrelevant feedback and 23.70% for the sham writer with relevant feedback. The context-only route also gave 24.09%. The actor does not receive the public candidate-law tables used by the reference. The 0.95 utility and 1.0 engineered Bayes accuracy cannot establish self-correction.
- **G, donor cap.** Uncapped training achieved 78.57% on the labeled executive metric, 10.55% post-tool accuracy and −0.479 utility. Projecting the final weight change down to the prescribed cap yielded 7.38% action success; the norm-matched shuffled cap yielded 6.43%. The parent and all children scored zero on the baseline family endpoint. This makes retention of a previously qualified skill unmeasurable.

### Reproducing the public-only executive control

Run from the Y4 implementation checkout. `true_answer` and the registered optimal actions are accessed only for scoring after the public-only decision.

```python
from experiments.avendi_y4.plan import STREAM_SEEDS
from experiments.avendi_y4.tasks import build_p5_blind_worlds

def choose(prompt):
    facts, options, _, query = prompt.split(" | ")
    rows = [t.split("->") for t in facts.removeprefix("FACTS: ").split(" ; ")]
    candidates = set(options.removeprefix("CANDS: ").split(","))
    visible = {v for _, v in rows} & candidates
    if len(visible) == 1:
        return (candidates - visible).pop()
    graph = dict(rows)
    return graph[graph[query.removeprefix("Q:")]]

for split in ("dev", "confirm"):
    worlds = build_p5_blind_worlds(split, 140, STREAM_SEEDS[split] + 500)
    correct = sum(choose(w["public_prompt"]) == w["true_answer"] for w in worlds)
    illegal = sum(any(a in ("QUERY", "RETRIEVE") and not w["available_tools"][a]
                      for a in w["optimal_actions"]) for w in worlds)
    print(split, correct, len(worlds), illegal)
```

Expected lines are `dev 140 140 5` and `confirm 140 140 5`. All post-run controls here used CPU. The analysis did not retrain any model or open a new confirmation set.
