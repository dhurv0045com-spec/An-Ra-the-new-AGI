## 2. The immediate correction: make readiness mean something executable

Replace one coarse data-ready boolean with explicit states:

`DECLARED -> MATERIALIZED -> VERIFIED -> QUALIFIED -> RUNNABLE`

Each transition has concrete evidence:

1. **Declared:** source registry, allowed usage, target mix and semantic split policy exist.
2. **Materialized:** referenced data bytes are accessible; generated cognition output exists.
3. **Verified:** content hashes, tokenizer identity, global deduplication and split separation match.
4. **Qualified:** the exact cognition generator/data pair passes its declared shortcut and correctness protocol.
5. **Runnable:** the actual loader reads those bytes into a valid batch and the selected backend completes a verified update.

Unknown is distinct from zero and from pass. Missing qualification blocks a claim of qualified cognition data. Registry presence alone is not a verified source inventory. A dry run must explain each remaining blocker with the responsible artifact identity.

### Correct cross-receipt accounting

Use stable document content IDs and a canonical union manifest. For each receipt, record its source namespace, upstream lineage, tokenizer identity and deduplication scope. Reject or reconcile overlapping receipts before reporting global unique counts. Repeated receipt submission must be idempotent.

The pair references two `foundry_st` receipts with the same document count but different token counts. That does not prove duplicate documents, but it requires lineage/overlap checking before summing them as independent supply. A token count under one tokenizer is not interchangeable with a count under another.

Add focused tests for overlapping receipts, repeated receipts, missing qualification, mismatched generator versions, inaccessible shard hashes, and insufficient qualified mixture supply. These exercise real readiness failure modes rather than mirroring implementation details.

## 3. Turn P35-A into a valid scientific comparison

The existing proposal specifies 35,411,328 parameters and 200M tokens per arm, with seeds 1 and 2. Treatment allocates 130M natural, 40M code/formal and 30M cognition tokens. Control allocates 153M natural and 47M code/formal tokens. The control allocation approximates the renormalized 65:20 ratio with integer-million rounding; record that rounding rather than calling it mathematically exact.

Required amendments before execution:

- Materialize the selected cognition generator and hash code, configuration and output shards.
- Replace pending preregistration identities with actual data/pair/pack/evaluation identities.
- Freeze a semantic-cluster split before rendering examples, including counterfactual query pairs.
- Confirm that simple copying, recency, positional and answer-frequency policies cannot explain the primary score.
- Match tokenizer, initialization seeds, optimizer, schedule, batch semantics and inference settings.
- Declare token accounting: capacity, real input, eligible targets and optimizer updates.
- State the primary estimand as the effect of the **whole mixture replacement**. Additional cognition necessarily displaces some natural/code exposure.
- Treat matched natural-validation-loss analysis as a secondary diagnostic. Conditioning on a result of treatment is not an independent randomized causal comparison.

The current rule-induction re-audit reports a Wilson upper excess of approximately 0.2182 against a 0.1 threshold. Increase qualification coverage or improve the generator before declaring that uncertainty resolved. Do not select qualification sample size after seeing a convenient favorable point estimate.

Run a cheap end-to-end pilot before committing both full arms and both seeds. Four 200M-token runs total **800M training tokens**, before evaluation and failed jobs. Actual TPU cost must be measured. The pilot establishes runtime feasibility and target validity; its outcomes do not replace the preregistered confirmation experiment.

## 4. Own the actual update, not only its report

The production path must connect:

```text
verified shard -> deterministic sampler -> segment-aware packer
-> tensor batch -> intended V5/P35 core -> canonical objective
-> backward -> finite check -> clip -> optimizer -> token schedule
-> measured parameter/moment mutation -> durable checkpoint
-> fresh-process restore -> verified continuation
```

Retain the orchestration layer if it is useful. Supply it with one canonical backend that owns tensors and derives evidence from the actual update. A backend self-report that gradients are finite is not a substitute for a test that observes the computation.

Minimum backend receipt:

- Model specification and parameter count, initialization seed and tokenizer hash.
- Batch content hash, segment IDs, eligible target count and source contribution counts.
- Pre/post parameter and optimizer-state fingerprints for a nonzero-gradient update.
- Loss components, finite checks, gradient norm and applied learning rate.
- Cursor, RNG and token counter before/after the committed update.
- Checkpoint content hashes and independent restore outcome.

Do not insist that every parameter change on every step; unused branches and zero gradients can be legitimate. Require expected trainable parameters and optimizer state to behave correctly on a deliberately informative canary.

Reuse Citadel's real packing/runtime/checkpoint work through a pinned adapter where it satisfies the canonical contracts. First verify one supported TPU topology. Add distributed reduction only when the actual deployment topology requires it, and then test that gradients and updates correspond to the intended global batch. Do not infer distributed correctness from metadata.

## 5. Add the learning machinery that P35-A does not test

P35-A asks whether a particular data mixture improves a particular capability. It does not test autonomous discovery. Extend the canonical learner with:

1. A versioned observation/action interface and recurrent state reset contract.
2. An experience store with task mechanism identities, outcomes and collection-policy provenance.
3. Predictive training on real transitions and a bounded action-selection policy.
4. Replay that mixes new experiences with retained training skills.
5. Parent/child model identities and promotion records from an independent evaluator.

Use the master blueprint's switch, inventory and program worlds. Start with one family. Prove that the agent learns from interventions with frozen weights before conflating that result with weight updates. Then test consolidation across multiple acquisitions.

The learner must eventually select experiences itself. A manually adjusted mixture can establish a useful curriculum baseline, but cannot establish learned curriculum selection. Keep both so the contribution of autonomy can be measured.

## 6. A realistic 100× improvement program

| Lever | Baseline to measure | Experiment | Disqualifying tradeoff |
|---|---|---|---|
| Data quality | Cost to reach fresh paired-query accuracy | Qualified diverse mechanisms versus repeated surfaces | Improvement only on generator templates |
| Packing | Real/eligible targets per accelerator second | Segment-correct packing versus current path | Cross-document leakage or changed loss weighting |
| Data pipeline | Accelerator idle time and host preparation cost | Cached/prepared batches with identical sequence | Changed sampling distribution or broken resume |
| Retention | Cost to reacquire old skills | Replay/consolidation versus sequential fine-tuning | Hidden loss in protected families |
| Experience selection | Task success gained per real interaction | Learned versus fixed/random collection | Extra feedback or privileged state |
| Recovery | Useful committed updates per session | Durable restore versus restart | Incomplete optimizer/sampler continuation |

A hundredfold reduction in wasted examples is a research hypothesis. A hundredfold parameter reduction is not a hundredfold increase in capability. Measure end-to-end cost at an unchanged target and report uncertainty. Improvements that do not compose should not be multiplied.

## 7. Ordered acceptance checklist

**C1 — Truthful inventory:** duplicate receipts cannot inflate unique supply; missing qualification cannot produce qualified-ready status; the exact P35-A generated output is linked to its qualification.

**C2 — Connected learning:** real data through the intended core changes expected parameters and optimizer moments, uses the correct schedule, and restores correctly in a fresh process.

**C3 — Interpretable acquisition:** the frozen P35-A comparison produces per-cluster outcomes with stopping and query sensitivity measured separately. Report a negative result if cognition replacement does not help.

**C4 — Interactive learning:** a learned investigator beats simple collection policies on held-out mechanisms at equal real-interaction cost.

**C5 — Durable improvement:** independently evaluated child models improve transfer while preserving protected capabilities across multiple acquisitions.

C1 and C2 are the immediate engineering work. C3 is a limited data-mixture study. C4 and C5 begin to address the missing self-improving intelligence. None alone establishes AGI.
