# Signac 100M readiness

## Current verdict

**Architecture and Kaggle qualification package: ready for bounded all-core TPU canaries. A production 100M training run is not ready or authorized.** Production `execution="xla"` remains fail-closed. The API has a separate, explicitly unqualified `execution="xla-development"` lane limited to one or two updates. The Kaggle notebook now exposes that real campaign path behind a disabled-by-default synthetic integration toggle; neither it nor the all-core canary has been run on Kaggle. Corpus, Citadel evaluation, exact multi-process resume, measured throughput, and peak-memory fit remain unqualified.

## Candidate geometries

| Candidate | Width × depth | Query/KV heads | FFN | Parameters |
|---|---:|---:|---:|---:|
| M102 primary | 640 × 20 | 10 / 5 | 1,600 | 101,790,080 |
| Depth-preserving TPU challenger | 640 × 20 | 10 / 5 | 1,536 | 99,332,480 |
| Fully tiled TPU challenger | 768 × 12 | 12 / 6 | 2,176 | 100,303,104 |

The 640-wide FFN challenger preserves M102 depth and changes only the FFN width. The fully tiled challenger changes several architectural variables and must win a matched systems and multi-seed capability comparison before promotion. At one sequence per replica and context 4,096, the naively materialized BF16 attention-score tensor is 335.5 MB per active layer for the 640-wide candidates and 402.7 MB for the 768-wide candidate; the target kernel may use a different allocation strategy.

```powershell
python -m pytest tests/test_signac_100m.py tests/test_v5_mutation_canary.py tests/test_v5_target_preflight.py tests/test_xla_development_campaign.py -q
python tools/signac_100m_preflight.py --target tpu
```

The second is expected to return `BLOCKED` until target, data, and evaluation evidence are supplied. A passing all-core Kaggle canary is still not production-run authorization.
