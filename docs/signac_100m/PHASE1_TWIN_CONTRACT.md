# Signac Phase-One Research Twin Contract

## Purpose and claim boundary

The Phase-One twin is the reproducible Signac research loop: freeze a capability hypothesis and run identity, train on qualified data, evaluate candidate-free behavior under controlled changes, test retention and recovery, audit the evidence, and promote or stop against criteria frozen before outcomes. “Twin” names this versioned research system. It does not mean an AGI copy, an autonomous AGI builder, or an AGI result. Parameter count, fluent output, loss reduction, and TPU utilization are engineering observations, not capability evidence.

## Separate verdicts

| Verdict | Meaning |
|---|---|
| `PACKAGE_READY` | Static architecture, code, and launch contracts pass local checks. |
| `KAGGLE_TPU_CANARY_PASS` | The actual free Kaggle TPU runtime passed bounded multi-device engineering canaries. This does not authorize a research training campaign. |
| `BOUNDED_RUN_AUTHORIZED` | All infrastructure, data, evaluation, and fresh-seed baseline gates below pass. Only the frozen, bounded experiment may run. |
| `PHASE1_EVIDENCE_COMPLETE` | The preregistered development, sealed confirmation, fresh replication, retention/recovery, and audit criteria pass. The claim remains limited to the specified capability and tested conditions. |

Verdicts never promote automatically: a canary cannot authorize a run, and one experimental result cannot establish a general AGI claim.

## Immutable run identity

Before target execution, bind the candidate name, exact `ModelSpec` hash and parameter count, source commit, and SHA-256 inventory of the source bundle. Source identity v2 includes the Kaggle launch notebook as well as the executable Signac dependency tree, and the same digest is carried through run identity, checkpoint, checkpoint-backed adapter, and Phase-One subject/evaluation receipt. Kaggle may omit Git metadata; the content digest remains mandatory. Also bind tokenizer hash, data/split/pack/mixture manifests, EOS and objective policy, optimizer and token schedule, precision, seeds, evaluator hash, Kaggle image/runtime versions, and observed TPU model/topology. Record global device count and process world size independently. Any missing identity, topology mismatch, mutable source, or receipt mismatch means `BLOCKED`.

The primary M102 geometry is 101,790,080 parameters. Its same-depth FFN challenger and fully tiled challenger are separate candidates; measured throughput or memory alone cannot promote either. Kaggle grants and queues vary, so use the accelerator actually provided and stop if it does not match the frozen target.

## Engineering gates

| Gate | Pass predicate and required evidence | Failure verdict |
|---|---|---|
| G0 — Static contract | Model inventory equals the selected exact parameter receipt; source, model, objective, optimizer, and data identities are content-bound; relevant local tests pass. | `PACKAGE_BLOCKED` |
| G1 — Kaggle runtime | In the actual Kaggle session, PJRT reports TPU; record actual Kaggle image, PyTorch, `torch_xla`, device type, global/addressable devices, and world size. The launch reports every expected unique rank and passes a cross-rank collective plus finite BF16 and device-RNG checks. | `KAGGLE_TPU_BLOCKED` |
| G2 — All-core useful work | During measured steady-state throughput updates, each intended rank consumes its planned non-duplicate shard and reports positive supervised tokens. A terminal short-tail update may leave a rank with zero eligible tokens only when its rows are fully ineligible padding; every rank still participates, and the positive global token total is conserved under G3. Synchronized warmup and at least 20 measured steady updates use the frozen production shape. Separate compilation from steady-state; record synchronized global tokens/sec, latency distribution, per-rank work, and instrumented peak memory. Require measured peak at or below 85% of usable per-device memory for the exact batch/context/accumulation, or revise the declared workload and rerun. | `KAGGLE_TPU_BLOCKED` |
| G3 — Numerical/update contract | On a frozen mini-batch, compare the distributed accumulated update with an independently computed single-device reference under predeclared BF16/FP32 tolerances. Verify finite loss and gradients, token-weighted global gradient, each rank's sampler-derived local eligible-token count, and the summed global denominator and loss numerator. A rank with zero local targets is valid only for deterministic all-ineligible short-tail padding: it contributes a graph-connected zero, participates in every collective/update boundary, and the rank counts must still sum exactly to a positive global denominator. Also verify one global mean-loss receipt, one global clip, exactly one optimizer step per accumulation boundary, tied weights, mutation, and independently reconstructed eligible-token totals. | `KAGGLE_TPU_BLOCKED` |
| G4 — Restart and durability | Compare uninterrupted N+1 updates with N updates, a fresh multiprocess restart, and update N+1. Verify model, optimizer, per-rank RNG, sampler cursor/next batch, and update receipts; test incomplete/corrupt state rejection. Publish atomically with rank-zero ownership, copy the checkpoint to durable Kaggle Output, and verify every hash after round-trip. | `KAGGLE_TPU_BLOCKED` |
| G5 — Data and evaluator | Corpus lifecycle is `RUNNABLE`; source/license, transform, tokenizer, deduplication, split, pack, contamination, and real-token receipts are hash-bound; source clusters do not cross splits. Citadel evaluator is frozen, independent, hash-bound, and passes its firewall, executable-truth, and EOS checks. | `RUN_BLOCKED` |
| G6 — Baseline sensitivity | Preregister Signac-specific floors, ceilings, minimum detectable effect, aggregation, familywise alpha, maximum simultaneous interval width, and distinct training seeds. The Phase-One gate reports simultaneous, Bonferroni-adjusted Hoeffding bounds over independent trained-subject/evaluation-surface rates when summaries qualify; decisions use these run-level bounds and remain inconclusive when any interval exceeds the frozen precision limit. These are development diagnostics, not an intervention effect or run authorization. Do not reuse S5 proxy thresholds as Signac thresholds. | `RUN_BLOCKED` |

`BOUNDED_RUN_AUTHORIZED` requires G0–G6 to pass with actual Kaggle TPU evidence for G1–G4. Synthetic data can pass engineering plumbing only; it cannot pass G5 or provide a capability result. Missing peak-memory instrumentation, exact distributed restart, or any rank receipt blocks authorization.

## Research evidence gate

G7 freezes one capability claim, training dose, endpoints, stopping rule, analysis, and thresholds before outcome inspection. It measures candidate-free exact answers with valid EOS, query-swap, order-swap, combined nuisance changes, structural out-of-distribution cases, intervention specificity, per-family and worst-family performance, and seed-level uncertainty. Loss remains diagnostic. After development criteria pass, consume the sealed set once; then run a fresh independent replication and matched retention/recovery tests. Report supported, unsupported, or inconclusive outcomes, including nulls, without post-hoc threshold changes.

`PHASE1_EVIDENCE_COMPLETE` requires the frozen run budget, sealed confirmation, independent replication, retention/recovery, and a separate audit of the durable evidence bundle. Even then, the permitted statement is limited to the named capability under the tested conditions.

## Executable Phase-One path

`signac_100m/training.py` builds two separately labeled development families through `v5_training.production_entry.prepare_data`: generated E0 cognition exercises with context/query/answer targets, and research records rendered from the cross-branch experiment ledger plus the curated Signac evidence index. Research records preserve status, evidence class, supported and unsupported claims, artifacts, and caveats. The machine ledger is a 2026-09-13 snapshot at its recorded basis commit; the curated Signac index carries the later S5 correction. The bundle records hashes for both sources and remains a development snapshot, not a live checkout of every research branch or a qualified production corpus. The E0 training-template namespace is checked against the separate E0 evaluation templates.

`signac_100m/phase1_eval.py` freezes an E0 development suite into a V5 evaluation fixture. The protocol binds the generator code, generator configuration, exact fixture contents, generic evaluator code, and Signac-specific scorer/gate code. Phase-One inference requires the canonical, immutable V5 adapter loaded through `CheckpointStore.restore`; that verifies the complete content-addressed checkpoint manifest and all seven component hashes before matching checkpoint, parameter, model, and tokenizer identities against the subject. Direct caller-supplied model payloads and adapter overrides are rejected. SHA-256 proves content identity, not authorship; subject custody still needs independent audit. Evaluation runs raw free generation with no candidate assistance, and records EOS versus length-limit termination. Causal-pair success requires both members to be correct and EOS-valid. The “naturalized analogue” task families are still generated synthetic templates; they do not measure natural-text transfer. This bridge rejects sealed/fresh inputs. `signac_100m/custody.py` now provides split-independent one-shot reservations for dataset, fixture, and source-cluster hashes, retry lookup, terminal failure recording, sealed/fresh cluster-disjointness checks, and append-only receipts. It stores no cases and runs no evaluator; the caller must claim before opening data.

`signac_100m/phase1_eval.py` distinguishes the training seed in the checkpoint subject from the evaluation-surface seed. Its baseline report validates family and skill-axis counts against one another, recomputes Wilson intervals, requires all seeds to share one source-tree identity, and, when trained subjects, evaluation surfaces, and recipes qualify, computes simultaneous Hoeffding bounds over equally weighted subject/surface rates with a Bonferroni correction across axes, EOS, and paired endpoints. Tasks and generated groups within a subject are first reduced to one bounded rate, so they are not counted as independent training replicates. The preregistered familywise alpha and maximum interval width are bound in the gate specification; all floor/ceiling/sensitivity classifications use the run-level bounds, while overly broad intervals force an inconclusive result. The bound is conditional on independent seed generation: unique seeds/hashes are recorded, but seed custody and randomization are not independently audited by this module. These estimates remain development-only; they do not estimate curriculum effects. The report always sets `mechanism_experiment_eligible: false`.

`CheckpointRegistry.transition()` cannot set `SEALED_EVALUATED` or `PROMOTED` from a caller-provided lifecycle string. `attach_sealed_confirmation()` accepts only a structurally valid passing custody receipt bound to the registered subject, attached development receipt, source tree, and training seed; it advances the subject to `SEALED_EVALUATED`, while promotion remains separately gated. The custody ledger binds externally supplied evaluation, evidence, custodian, and independent-review hashes, but neither component inspects those artifacts or verifies reviewer authorship. These methods enforce process and content identity, not external qualification; real corpus, evaluator, and independent-audit receipts remain required, and a development evaluation receipt cannot substitute for sealed confirmation.

Registry mutations use per-subject exclusive writer locks and atomic entry replacement. A stale lock blocks later writes for explicit inspection. This protects local registry updates; it does not satisfy G4's separate Kaggle Output durability and hash-round-trip evidence.

`signac_100m/rsi.py` is a deterministic weakest-axis diagnostic plus a preregistered matched-development-trial analyzer; it is not learned recursive self-improvement. The diagnostic recomputes the baseline gate against the supplied preregistration and exact summary hashes, reports a weakest skill axis when possible, and always abstains without changing skill-axis weights. `RegisteredCurriculumTrial` freezes the direct training-family/target-axis mapping, control and treatment curriculum identities, minimum matched seeds, familywise alpha, interval-width limit, target effect, and tolerated off-target harm. `analyze_registered_curriculum_trial` requires each arm in a pair to share its training seed, exact evaluation suite, and source tree, and to match on every other core recipe identity exposed in the summary; it then computes simultaneous paired Hoeffding bounds over the cognition and paired-outcome metrics. The subject-manifest digest does not expose every recipe field, so full component equality, randomization, and source custody still require independent audit. Broad intervals remain inconclusive; a development effect signal only points to fresh sealed matched confirmation. Trainer mutation, training authorization, and model promotion remain false. Phase-One summary v5 includes pair success and valid-EOS rates by evaluation family and pair kind, plus exact/EOS rates for each cell of the interference-retrieval grid. SHA-256 bindings detect content changes; they do not establish authorship or replace custody and independent audit.


These tests qualify deterministic construction and measurement plumbing only. The oracle adapter is test-only and is not accepted by the production Signac evaluation entry point. Tests do not execute M102 training, establish a sensitive baseline, or pass any Kaggle TPU, real-corpus, sealed/fresh, or production-run gate.

## Current evidence boundary

The Kaggle notebook now includes a bounded `torch_xla.launch` canary requiring eight visible TPU devices. Automated receipts do not identify the chip SKU or Kaggle image build, so target-specific claims must retain those details separately. It verifies participating ranks, a collective, synthetic rank-distinct batches, global gradient averaging before clipping, synchronized updates, replica state hashes, and runtime memory counters. Its unequal-rank FP32/BF16 tiny-model parity probe compares the distributed global-denominator gradient against a single-device global-batch oracle; this does not qualify numerical parity for the full Transformer. Its M102 option writes the replicated model/Adam checkpoint after update one, saves each rank's CPU and XLA generator states and versioned synthetic stream cursor, starts a fresh worker group, and compares a replayed XLA random probe, resumed stream suffix, restored/final rank RNG and cursor states, and parameter/optimizer hashes with the uninterrupted two-update path. The canary verifies the notebook-computed source-tree digest against the live snapshot before launch, binds it into each rank/restart/aggregate receipt, and requires matching nonempty Python, PyTorch, `torch_xla`, and platform metadata across ranks and the restart group. These checks remain unrun until a Kaggle TPU session is actually available. This synthetic restart is narrower than production exact resume: it does not certify the production packed-data bucket-lane sampler, durable output round-trip, full-model distributed numerical parity, the 20-update measured workload, data, evaluator, or baseline gates. The production V5 path still rejects XLA pending target certification.
