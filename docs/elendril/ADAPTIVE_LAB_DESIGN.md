# Independently verified adaptation

Use a frozen reference and a bounded candidate branch for each intervention. An append-only decision receipt links the observation, diagnostic, intervention proposal, cost reservation, candidate identity, verifier receipt, decision and rollback checkpoint. The adaptation loop should progress only after each task clears independently measured formation and anti-shortcut controls.

| Authority | Inputs and authority boundary |
| --- | --- |
| Learner | Development prompts, authorized training data and a capability-limited fork of a parent state. It can propose changes and submit predictions. |
| Test custodian | Owns prospective task and truth generation, split assignment and unlock. Releases visible tasks through an authenticated verifier channel. |
| Verifier | Executes fixed budgets, admits complete prompts plus generation reserve, commits predictions before joining truth, scores with independently implemented oracles and shortcut baselines, and signs the exact task and code identities. |
| Promoter | Separate owner-controlled service. Validates hashes, complete coverage, predeclared effect and cost gates, retention, safe rollback and authorization before atomically switching the reference pointer. |

First isolate external memory or strategy changes with weights frozen. Scope memory by task and commit the store contents and tool traces. Compare retrieval against fixed replay, an empty store and an equal-cost simple policy. Then test bounded weight updates in isolated lineages with fixed architecture, checkpointed optimizer and same-cost replay baselines. Retain the parent and optimizer for rollback. Test architecture changes last, with an explicit migration map, parameter and compute budgets, randomized assignment, and a parameter/compute-matched fixed-architecture baseline. Acceptance requires measured benefit on prospective tasks, across declared retention and transfer endpoints and resource units. An architecture gate receiving gradients is engineering telemetry.

The controller experiment randomizes task blocks and compares a learned selector with fixed, random and heuristic selectors given the same intervention catalogue, input history, number of trials and compute. Evaluate candidate ranking, realized improvement per reserved resource, selection regret, and cross-block transfer. Preserve failed and truncated trials. Charge training, evaluation, model calls, tool calls, storage and intervention trials to each parent budget. Validate the actual serialized proposal plus output reserve under the real tokenizer before spending training resources. A verified transfer win under fixed selection would still leave learned intervention selection open.

Run the roles in separate trust domains for prospective promotion. Keep scoring code, release keys, truth and mutation privileges outside the learner environment. The current CPU instrument supplies development receipts and local checkpoints. It has no autonomous promotion or mutation authority.
