# One working ELENDRIL episode

The active path is `observe → propose → execute → verify → consolidate`. A bounded goal identifies the current world and one declared reusable public scope. Observations carry subject, source, tick, identity and ancestry. The ledger preserves explicit null, missing values, source disagreement and later revisions. Repeated identical evidence does not add a second vote. Model hypotheses stay separate from the ledger. The revision prompt explicitly encodes missing, null, conflict and derived states, while route rendering retains the checkpoint's established grammar.

The same frozen two-read ELENDRIL checkpoint produces raw answer or operation tokens from the public symbolic state. Its answer requires an actual EOS. The controller validates proposed operations, channel IDs and costs, then executes only public actions. The verified outcome joins against a separately supplied truth record. A memory update stores only admitted public event IDs and their payloads, under a version hash and a strict capacity. The verifier interface is separated in-process. A sealed evaluator or untrusted candidate execution needs an external isolation boundary.

The model was pretrained for two-hop answer generation. The small action token mapping is untrained. It permits the host to observe any action the model actually proposes. There is no oracle fallback. The demo uses fixed prefetch for its memory arm, charges it as a request and retains its fixed origin. The answer remains model-origin. The natural-language display is for the operator, while the model receives a symbolic evidence rendering.
