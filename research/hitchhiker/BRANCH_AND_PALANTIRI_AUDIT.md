# Hitchhiker and Palantiri research audit
Reviewed at c22a3532be8c10cf45cc33c82d47c5e8e431cc71 on 2026-11-18.

**Decision. Keep the runtime, checkpoints and evidence tools. Redesign the unit of evidence around a family of questions for which the competing mechanisms must give different answers.** The next GPU expenditure I would authorize is a frozen-checkpoint evaluation. The first new engineering work I would fund is making Palantiri verify the exact behavioral claim a run advertises.

## What the experimental history says

V6 recorded 16/16 useful initial queries and only 2/16 correct terminal answers on missing evidence. V7 subsequently recorded 73/96 both-correct changed-payload pairs under blocked training. The learner can use changed evidence in some distributions. V7.17 showed a strong learning-rate effect at S20 alongside failure on novel chains. Hitchhiker then produced 256/256 ordered four-hop answers for C seed 7, all explained behaviorally by copying the final row across 768 order variants. These observations argue against both a universal inability to use evidence and a general claim of traversal. [V6](../../Experiment%20Result/V6/RESULTS.md) · [V7](../../Experiment%20Result/V7/c9981309a94847a4a97d8115c56d75c8/RESULTS.md) · [Hitchhiker](../../Experiment%20Result/Hitchhiker/hh-stage1-4bfe3a806e3b/RESULTS.md)

Y1 exposed a sharper failure. F11 gave exactly the same token sequence on 767/768 paired questions across three seeds when the graph stayed fixed and the correct answer changed. Increasing S3 to S20 under the registered schedule gave lower mean accuracy on both tested arms. A public timestamp-rank rule solved 3,072/3,072 primary presentations across the three archived splits. The same raw records can establish the query failure while leaving the learned internal algorithm undetermined. I would give that paired failure more weight than the average accuracy or the parameter count. [Y1 audit](../../Experiment%20Result/V8-Y1/y1-all-9c80885013/RESULTS.md)

**The recurring design mistake is changing how often a behavior is rewarded when the missing evidence concerns which input causes that behavior.** Increasing unavailable cases gives abstention more training signal. Fresh worlds vary entity assignments. Neither manipulation requires a learner to give two different correct answers to the same facts because the question changed. A data generator can produce millions of unique strings while teaching the same accidental rule each time. Additional seeds measure variation in learned models while a deterministic generator defect repeats across all seeds.

Split the research program into acquisition, selection and composition. First measure whether a model can select the requested single edge when answering is always appropriate. Then ask whether an internal bridge changes a three-hop answer. Finally vary whether the evidence is sufficient and measure the choice to query or abstain. Keep the final interactive task as a transfer test. This ordering reveals the first failing dependency. Attributing a failure to catastrophic forgetting requires a skill the same model had already acquired on withheld families before the next training stage.

## What Palantiri already buys you

The public entry point is Palantiri and the implementation package is Planthir. The V8-Y1 owner run used its own campaign harness. The branch also carries a historical Palantiri/Planthir GPU validation on a laptop RTX 4050 with four small arms, 60 updates per arm, and 24 evaluation worlds. All four recorded zero overall accuracy while the five engineering gates passed. The later upgrade records CPU qualification of the declarative runner and subprocess recovery. The historical 82% token-saving figure was an estimate. The paired productivity study still needs observations. I reran the current calibration on CPU and reproduced six detected faults and a passing healthy fixture. [GPU record](../../Experiment%20Result/Planthir/EXP_PLANTHIR_004_LIVE_GPU_VALIDATION.md) · [Reliability review](../../Experiment%20Result/Planthir/reliability-2026-11-16/RESULTS.md) · [Upgrade](../../Experiment%20Result/Planthir/upgrade-2026-11-17/RESULTS.md)

Keep atomic checkpoint publication, explicit resume, manifest-bound exports, negative controls and the structured experiment specification. They let another investigator return to a particular model and observation. The X1 adapter already has a query-conditioned pointer, slots, edge messages, a no-edge arm, a capacity control and grouped counterfactual losses. Reimplementing those components from scratch would spend time before identifying the failing operation. One important architectural boundary is that X1 computes its operation head from the backbone state before the relational path changes the value pointer. A lesion of that path can directly test value selection. Its effect on the winning decoded action can also arise from redistributing probability among the sixteen answer symbols. Interpret changes in the operation logits and value logits separately. [X1 model and loss](../../anra_v5/planthir/adapters/x1_rd2_adapter.py)

A successful load and forward pass is valuable but leaves agreement on original evaluation worlds unresolved. | Expose separate restore, probe and original-prediction agreement fields. | 3. Calibrate statistical conclusions | The paired-seed helper returned two-sided p=0 for three identical +0.25 differences. Its zero-standard-error branch makes this choice explicitly. ## The experiment I would run first

Use two equal-length routes. In one version the facts are A→C, B→D, C→E, D→F, E→G, F→H. In the other, exchange the destinations of the two middle edges. Ask both possible start questions against both graphs.

| Three-hop query | Original middle edges | Exchanged middle edges |
|---|---|---|
| Start at A | G | H |
| Start at B | H | G |

The set of symbols, their frequencies, the two endpoints, and the number of facts stay identical. Within each graph only the query changes. Across graphs only the two middle bindings change. The primary score gives one point for getting **all four** answers correct. Any deterministic policy that ignores either the question or the rewiring must repeat an answer on a pair whose correct answers differ, so its complete-family ceiling is zero. This argument holds even for a shortcut nobody thought to register within those two classes. A specialized rule that reads both inputs can still pass, so an additional graph grammar and unseen path depths are needed before claiming general traversal.

I implemented a CPU prototype with eight distinct sampled symbols per family, shuffled fact positions and independently sampled timestamps, held fixed within the family. It evaluates the graph semantics directly. With seed 1801 the traversal oracle solved 256/256 families. Last-object and third-earliest-timestamp rules scored 182/1,024 and 164/1,024 individual cases and zero complete families. Two controls given the endpoints and perfect information about only one of the two factors each scored 512/1,024 and zero complete families. These are new fixture measurements. Scoring a saved neural model requires the public renderer and checkpoint loader. [Runnable pilot](../../tools/audit_query_bridge_crossover.py)

**First owner run.** Use Y1 S3 F00 and F11 at seeds 7, 19 and 41, frozen. Resolve checkpoints against the Y1 receipts. First validate the exact rendered/tokenized input received by the learner with an independent parser, and test that deleting the question creates identical observations with conflicting golds. Add a companion one-hop lookup control with two distinct targets on the same table. Report raw exact answers, four-correct families, same-token-output rate, conditional A–P rank and log odds of G versus H in each cell. Report directional log-odds flips even when greedy outputs stay unchanged. This distinguishes a weak but real query signal from complete output insensitivity. Keep the previous primary endpoint solely for continuity. If only older Hitchhiker weights are available, label this as historical-model diagnosis and report Y1 restoration pending.

**If single-hop selection fails**, compare ordinary CE with CE plus the existing counterfactual answer margin using identical four-view batches, data order, initial tensors and update count. Build the pairs from the crossed questions and rewires. Report eligible contrast counts and actual gradient contribution. Include same-case unary supervision in both arms so the experiment identifies the effect of the extra objective. Test three matched seeds and reserve an independently generated holdout before selecting models. A positive decision requires a raw complete-family improvement in every seed and preserved one-hop correctness. Register a practical minimum, for example ten percentage points of mean family improvement, before training. Report both metrics when they disagree.

**If lookup passes but composition fails**, my higher-risk idea is a learned single-symbol intermediate state that can be exchanged between two executions. Give the learner three applications of the same transition over public facts. Its only changing state is a distribution over the current entity. Prevent the final readout from bypassing that state via the original query or an unrestricted history. During diagnosis exchange the state after hop one between the A and B executions of the same graph. If it carries the operative intermediate, the answer should follow the donor's remaining route. Add identity swaps, a wrong donor, an oracle-provided intermediate, and terminal-edge changes. Compare against equal-depth dense computation, and separately record any privileged intermediate supervision. Learned traversal, benefits from an engineered state restriction, and benefits from extra labels are different empirical questions. A positive result on unseen lengths plus predicted donor-specific swaps is stronger evidence of a reusable transition than a high final accuracy alone. The limitation is deliberate: a symbol bottleneck encodes assumptions about the task and may transfer poorly to uncertainty or conflict.

## Spending decision and scope

Spend the next development cycle on prediction-agreement replay and the crossed-query fixture. Then evaluate existing checkpoints. Allocate another training matrix only after identifying whether the first failing dependency is lookup, composition or action choice. I would revisit larger models when an observed, controlled bottleneck makes size a discriminating variable.

This audit sampled the scientific history, the current Palantiri interfaces and selected implementation paths on hitchhiker. The new executions were CPU calibration, registry and statistical probes, X1 group inspection, and a reference-policy fixture pilot. Prior GPU results and the 464,880-episode Y1 replay come from the linked records. A full platform requalification, a rendered neural crossover result, and a measured productivity advantage remain open.
