# ELENDRIL V7 focused protocol

Status: **preregistered design, not a completed experiment**. This is a bounded study of public-evidence use and training order in the existing synthetic task. A failure is informative; no score-contingent tuning, selective stopping, or claim of general intelligence follows from this protocol.

## Question and fixed design

Can the S3 learner answer from a supplied public observation, follow a changed payload, and retain the interactive query policy as training order varies? Compare uniform mixing, blocked uncertainty-first ordering, and interleaved uncertainty/rehearsal ordering for seeds **7, 19, and 41**. Each seed starts from fresh weights; the archived V6 checkpoint tensors are unavailable. The historical execution source is `381195e17b0252220115c64eafb2e9f67d58416b`, not a frozen V6 model baseline.

For each seed, use the same generated training-world and example multiset for all three orderings. Fix order construction and randomness before observing scores, log the resulting sample order and exposure, and retain exactly the same per-epoch examples, batch and optimizer settings, and total example exposure, updates and unpadded input-token work. Ordering and padding can change actual compute; do not claim exact compute matching. Uniform uses a seeded shuffle. Blocked places missing/conflict examples first in epoch 0 and uses the uniform order in later epochs, reproducing the V6 ordering distinction. Interleaved spreads every category throughout each epoch in proportion to its share, using seeded within-category order. Neither creates extra training examples. A common, declared four-epoch optimization horizon and schedule applies to every run, including intermediate checkpoints; do not restart the schedule at each measurement. Train through four epochs even if early results are poor. No larger model, extra arm, extra epoch, or adaptive change is authorized by this design.

Freeze development worlds at generator seed **707** and confirmation worlds at seed **909**, **112 worlds each**. Verify disjoint world and public-state identities using the dataset audit. Select the fixed **28-world** development monitoring cohort before any model outputs, with its case IDs and selection rule recorded. It is the same cohort for every arm, seed, and checkpoint. Evaluate the 28-world development monitoring cohort at **0, 1/8, 1/4, 3/8, 1/2, 1, 2, and 4 epochs** as `diagnostic-u*.json`, including the whole-epoch milestones. Independently evaluate all 112 development worlds at **1, 2, and 4 epochs** as `development-u*.json`, and all 112 confirmation worlds at **4 epochs** for every arm and seed. Evaluate a fixed 28-world training monitor, selected as four per kind sorted by world ID, at **1, 2, and 4 epochs** as `training-u*.json`; compare fitting with held-out behavior without selecting cases by performance. Record actual update and exposure counts and retain per-case results. Confirmation is held out from design decisions and is not a source of tuning. If a frozen dataset or fixed schedule cannot be constructed as specified, stop and record the discrepancy rather than silently alter the study.

## Diagnostic and interpretation

At each evaluation use one frozen checkpoint for all conditions. The interactive condition receives the original public world and may query, with four decisions and two requests. The supplied condition appends the actual public channel payload to initial observations and removes advertised channels; it has three decisions and two requests. Account separately for its engineered exogenous release and do not count it as a model call or model-chosen query. The truth and admission set are unchanged, and neither truth nor labels reach the actor. Score truth only after the episode. The intervention bypasses query choice; it does not supply a gold answer.

Use every case in the selected cohort, and additionally evaluate both original and changed payloads from the deterministic V6 payload-swap pairs in both conditions. Report pair denominators and both-correct outcomes. Separately report the existing direct-known cohort. Direct-known and supplied examples are not a matched triad: a stateless model can receive an identical rendered prompt in different histories. Where a model actually queries and proceeds after receiving the same payload, compare its subsequent prompt exactly to the supplied prompt and report whether it is identical. Prompt equality limits claims about distinct internal mechanisms; it is not evidence that one exists.

Report per condition, kind, seed and checkpoint: non-null answer accuracy and denominator; null correct abstentions and denominator; query-needed recall and needless queries; invalid actions; raw answers, dominant answer and answer entropy; full payload-pair outcomes; model calls, positions, requests and utility accounting. Preserve per-episode raw action and prompt receipts and frozen-checkpoint identity. Candidate causes remain unresolved hypotheses: collapse, failure to extract supplied evidence, query-to-answer transition, and ordering/forgetting must not be inferred solely from aggregate accuracy. An observed loss of query recall over checkpoints establishes a trajectory, not by itself a forgetting mechanism. Train-versus-held-out results and counterfactual pairs help discriminate explanations without proving one.

Optional bounded probes use at most the first eight non-null supplied cases sorted by world and case ID, independently of performance. The input is the already-public supplied prompt; gold is joined afterward as a label to read the first value-token distribution and NLL. The value-to-EOS score is explicitly teacher-forced and cannot substitute for a free-running answer; no oracle is used to choose a decoded action. Probe calculations use no gradients, and record backend identity. Report them as auxiliary evidence.

## Execution and custody

Before an owner-authorized GPU campaign, run GPU availability, binding, deterministic data/order, context-length and checkpoint/resume canaries; audit target shifting, EOS and supervision masks on hand-checked public examples. Fail closed if any canary or replay fails. Record hardware, software, seeds, source and data identities, full schedules, input positions, supervised tokens, updates, padded input positions, attention pairs, peak memory, and GPU reservation and actual wall time, distinguishing training from evaluation and overhead. Preserve immutable receipts and independently replay the raw episodes with the versioned V7 measurement. Local preparation and tests do not constitute model training or experimental results.
