# ARK-019 V3 EXECUTION CLARIFICATIONS

**Status:** FROZEN BEFORE V3 IMPLEMENTATION / EXECUTION.

These points clarify implementation details in `PLAN_V3_R2_INFORMED_ADDENDUM.md` without changing the causal question, arms, thresholds, seeds, horizon or primary success rule.

1. **Movement telemetry:** full-model displacement from the matched parent is measured at every 100-step evaluation boundary. Per-step movement telemetry uses a fixed projected parameter set for ordinary uncapped steps to avoid cloning the ~21M-parameter model on every update. When CAP16X is active, raw and applied **full-model** step delta norms are measured exactly because projection requires the full pre-step state. The 32-step LOW cap-calibration shadow also measures full-model step deltas exactly.
2. **Durable checkpoints:** full model+optimizer checkpoints are written every 300 updates and at the final step, while lightweight JSON trajectory/health receipts are written every 100 updates. This supersedes the draft sentence saying full checkpoints every 100 updates; writing multi-hundred-MB optimizer checkpoints that frequently would create large Drive I/O overhead and threaten the 3-hour scientific wall without adding information.
3. **Replay dose accounting:** each update always has 32 objective slots. A no-replay update is 28 real-text + 4 SKILL_B. A replay update is 27 real-text + 4 SKILL_B + 1 SKILL_A. Thus 1/64 means one SKILL_A slot on exactly every second update, and 1/32 means one on every update. The displaced real-text slot identity and token count are recorded.
4. **Slot-normalized objective:** each real-text sequence contributes its mean token loss as one slot; each binding example contributes answer-token cross entropy as one slot. The 32 slot losses are averaged. This keeps the intended 7/8 versus 1/8 sequence-level pressure and makes replay replacement exact at the slot level.
5. **QUERY_ORDER metric:** canonical evaluates all three queries in canonical fact order; ORDER_ONLY uses reversed fact order; QUERY_ORDER deterministically moves the queried fact to the final fact position while preserving the order of the other two. This is distinct from canonical/reversed evaluation and is frozen before outcome observation.
6. **Runtime calibration:** the operator launcher measures representative mixed-update and evaluation time on the actual T4 and fails closed if four matched sets x four arms x 1200 steps plus parent acquisition/evaluation cannot fit under the preregistered wall with safety factor. Calibration may not change horizon, seeds, arms, thresholds or replay doses.
7. **No raw parquet dependency:** V3 consumes only the exact ARK-018 prepared tokenizer/train/control/sealed caches and completed SCIENCE_ONLY checkpoints already on Drive. It verifies the prepared receipt/cache/checkpoint identities before training and does not reread or re-tokenize the 1GB source parquet.
