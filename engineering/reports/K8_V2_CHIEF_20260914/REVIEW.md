## Required corrections

1. **Slot scheduling and exclusive devices.** `runner.run_campaign` reserves and dispatches all pending workers of a phase together. E1 has four jobs; the actual reservation API admits all four, including two on each GPU. `run_phase_concurrently` starts them together. This violates the two successive paired slots. E3/E4 likewise need successive treatment slots, not all treatments concurrently. Represent slots explicitly and reserve only the current slot, close it, then advance. Open time totals are not exclusive occupancy. Reject a second active job on the same physical GPU, even when total reserved seconds fit.

2. **Device remapping.** `_child_execute` sets CUDA_VISIBLE_DEVICES to `1` for a cuda:1 spec but passes cuda:1 unchanged into the worker. A process with one visible GPU addresses it locally as cuda:0. Preserve physical identity separately, map worker-local device correctly, and verify the physical UUID after initialization. The diagnostic observes exactly `visible=1, received_device=cuda:1`. Parent device reports are not proof that the child uses the assigned hardware.

3. **Actual termination.** `_run_one_in_process` calls executor shutdown with wait=False; it does not terminate an already running job. The diagnostic proves the finite child survives. Use explicit child-process ownership with terminate, bounded join and a final kill fallback where supported. Publish timed_out only with termination status and retained partial accounting. The agent's `hang_terminated` probe only times out a separately constructed ThreadPool future; it does not exercise or prove production termination. Replace it with the production worker-path check.

4. **Live lease ownership.** `SupervisorLease.acquire` treats lock age over 1,800 seconds as stale even when the PID is alive. The diagnostic forces a live PID and old timestamp and successfully reclaims the lock. An eight-hour session will naturally cross this age. Age alone cannot prove a writer is dead. Use an ownership token, conservative liveness check and fenced recovery; release must only remove the releasing owner's lease. Do not use Windows os.kill(pid,0) as a liveness probe: use an appropriate non-terminating platform API. Test with mocks and disposable fixtures, never by probing unrelated user processes.

5. **E0 never commits its advertised updates.** `training_step_full` returns `accumulate_full_window`, which performs backward and returns a dictionary; neither the helper nor its loop calls finalize_update. The subsequent state_payload requires a clean optimizer boundary. Thus the claimed six-update E0 cannot complete as written. Add an explicit canonical update boundary and derive consumed updates from actual counters. Do not merely write `committed_updates: 6` into a receipt.

6. **Resume remains invalid.** The restored trainer_c has require_allocation=True but no newly validated allocation attached. Its subprocess restore proof hardcodes a tiny CPU/non-AMP trainer, which rejects a CUDA AMP payload; continuation still happens in the parent process. Implement the full checkpoint/config/RNG/cursor/scaler/allocation contract and perform the resumed updates in the child using the same precision and profile. Preserve exact identity checks and a preregistered numerical tolerance where needed. A profile descriptor is not full-model timing calibration.

7. **Objective normalization still depends on entry path.** `accumulate` routes a token mean, marks `_pending_normalized=False`, and finalize divides those gradients by token count again. Repeated full-window calls normalize each microbatch separately instead of one complete accumulation window. Pair rows are collected without a corresponding pair-loss consumer. Choose one explicit optimizer-window contract; verify unequal microbatch partition invariance with backward-only checks. Reject missing eligible terms. Real learned performance remains a later check.

8. **Data qualification and export are incomplete.** Meta mechanisms are generated separately from primary-pool exclusion, and validation reconstructs a weaker key than generation. Qualification must use one declared canonical identity across all relevant pools and concrete protected task references. Teacher answers in labels or legitimate tool feedback are not automatically leakage; establish separation at the actual public renderer and independent environment verifier. Export now writes five JSON files, but checkpoint names in restore_evidence.json are not payloads. E6 checks file existence rather than producing/verifying the complete required artifact bundle. Build the canonical source/data/protocol/results/payload export and prove restoration before claiming durability.
