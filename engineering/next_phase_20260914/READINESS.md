# When BRAMASTRA is ready for the experiment

There are three distinct states. **Code-ready** means the complete intended paths exist and have passed local integration checks. **GPU-qualified** means the owner-launched E0 has verified those paths on the actual two T4s within the allocation. **Experimentally supported** means valid E1–E5 comparisons provide evidence for particular mechanisms. None is synonymous with AGI.

## Code-ready acceptance

- O01–O10 each has exact changed production symbols, focused command results and linked evidence. No executor relies on a fixture-only branch for its production result.
- Every training job attaches the actual reservation to the learner and reaches one correct optimizer boundary under a local no-op substitute. Missing authority fails. Window gradients are partition-invariant under controlled deterministic conditions.
- Checkpoint publication and parent restoration work through real payloads, hashes, config/architecture identities, RNG/cursor state and writer fencing. Wrong-parent and corrupt-payload cases fail.
- E0 calibration and protocol freezing consume injected timings locally and cannot select settings from learned scores. Runner uses the frozen artifact rather than hardcoded minima.
- Cognitive adapters execute different declared policies over matched cases. Environment actions, observations and final task verifier results are real. Model/control origins and costs are traceable.
- Tool and architecture treatments train/evaluate the exact restored/migrated handles named in their receipts. Protected material is excluded from updates.
- Production RSI trial execution trains/evaluates through its real interfaces; proposer output comes from the model interface; P1 and P_fixed updates consume matching resources and archive data. Locally injected learners are explicitly fixture-labeled.
- Full artifact export contains real required test payloads and restores them in a fresh process. Metadata-only output cannot satisfy completion.
- The notebook accepts inspected input/output paths, prints source/data/configuration identities and the single eight-hour allocation, checks command failures and does not reset E0 cost when entering full mode.

Passing these criteria allows the chief to mark the build ready for the owner to run E0. Do not require successful research results in order to declare code readiness; that would make the experiment impossible to start. Conversely, do not call missing implementation a GPU-only check.

Verify two distinct physical GPUs, worker-local device mapping, actual full-profile gradients, intended parameter changes, identical uninterrupted/resumed treatment, fresh-process continuation, next-batch state and bounded timing. Charge every attempted update and retry. Freeze the selected profile/microbatch/window/update targets/case inventory before E1. If a gate fails, retain evidence and refuse learned phases; do not substitute a tiny profile or a fixture receipt.

The campaign stops new training by minute 450 and exports by minute 480. E0-only and full mode share the same immutable allocation. No new quota is created by this phase document or by a kernel restart.

## Result interpretation and next milestone

Apply the original paired-seed, mechanism-cluster comparisons and protected-family constraints. Report engineering invalidity separately from valid negative results. A modest valid result is more informative than a large unsupported claim. For every mechanism record keep, disable, diagnose or replicate, with the supporting outcomes and uncertainty.

Only after valid evidence should a later proposal expand long-term memory, autonomous curriculum choice, richer architecture search, open-ended tools or multi-generation RSI. Rank those proposals by the measured bottleneck, expected information and adequate compute estimate. Do not launch them inside the existing session or promise a multiplier before measurement.
